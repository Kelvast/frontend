as a `Uint16Array(4)` (8 bytes):<br>`[r, s, t, id]`<br>* **r**: Request type (0-15 registered types)<br>* **s**: Skill ID (0-31 per SKILL_REGISTRY)<br>* **t**: Resource type / amount / context (0-255)<br>* **id**: Entity / Tile / Player ID (Encoded via `encodeTileId`)<br>### Security: XOR + HMAC-2B<br>Messages are secured using a per-session XOR encryption with HMAC-2B tamper-proofing.<br>* **Packet**: `[encrypted_8b] + [hmac_2b_sig] = 12 bytes total`.<br>* **Key Exchange**: Server generates a 32-byte `sessionKey` on connection, delivered over WSS (TLS).<br>* **Anti-Tamper**: HMAC signature verified before decryption; nonce increments per message.<br>### Message Registry<br>| r | Direction | Message | Description |<br>|---|---|---|---|<br>| 0 | Inbound | `action_start` | Begin gather/action (anim sync) |<br>| 1 | Inbound | `action_finish` | Complete action (server rolls) |<br>| 2 | Outbound | `player_state` | Nearby player state change |<br>| 10| Outbound | `tick` | Nearby player delta positions |<br>| 11| Bidirectional | `ping` | Latency check |<br>| 12| Inbound | `move` | Click-to-move target tile |<br>---<br>## World Architecture<br>### Coordinate System<br>* **World Tiles**: Integer coordinates `(x, z)`.<br>* **Chunk Formula**: `chunkX = Math.floor(x / CHUNK_SIZE)` (where `CHUNK_SIZE = 16`).<br>* **Local Position**: `localX = x % CHUNK_SIZE`.<br>* **Pixel Conversion**: `worldX = (chunkX * 16 + localX) * 32`.<br>### Loading Strategy<br>1. **World Map**: Region metadata.<br>2. **Terrain**: Chunk-based tile data (client-driven LRU cache).<br>3. **Entities**: Dynamic layers (players, then NPCs).<br>---<br>## Project Status<br>### What Is Built<br>| Feature | Status |<br>|---|---|<br>| Next.js Shell & Auth | ✅ Built |<br>| `GameEngine` &
